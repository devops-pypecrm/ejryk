# Zenitzu Tech Solutions: project instructions

We are an IT consulting and software development agency in Edappally, Kochi, Kerala. We plan, design, build and grow websites, apps and software. Our promise is speed: an idea live in days, not months.

## Always
- Read `context/` before producing client-facing or public work.
- Write in the voice described in `context/brand-voice.md`. Follow `context/style-guide.md` for colours, fonts and layout.
- Only promise the timelines in `context/services.md`. If unsure, say "typical" and "confirmed in writing before we start".
- Save every deliverable in `outputs/<type>/` with a dated filename, e.g. `outputs/proposals/2026-11-acme-website.md`.
- Never invent clients, prices, testimonials or statistics. Mark anything unknown as `TODO: confirm`.
- A human reviews everything before it is published or sent to a client.

## Agent routing
Use an **agent** when the task needs research, judgement or synthesis across sources. Use a **skill** alone when the task is straightforward execution.

| Task | Use |
|---|---|
| Market, competitor or keyword research | `researcher` agent |
| Campaign plan, positioning, proposal strategy | `strategist` agent |
| Blog, social copy, case study, email | `content-creator` agent (skills: blog-writer, social-posts, case-study) |
| Carousels, ad creative, visual direction | `designer` agent |
| Reports, dashboards, lead and task metrics | `analyst` agent |
| A single proposal or report from known inputs | `proposal-writer` skill directly |

Complex requests (a full campaign) run in this order: researcher > strategist > content-creator + designer > analyst (measurement plan).

## Handling work
- New website enquiries arrive in Admin > Leads. Follow `sops/lead-handling.md`.
- Team tasks live in Admin > Tasks. When finishing a task, put the output file path in its Output field.
